# v0.3.0 — release notes (draft)

**Not published.** This describes the state at the tip of `main` and is written
ahead of any tag. Nothing has been tagged, built or uploaded.

Previous release: [v0.2.0](https://github.com/rinatrizvanov/seq2lead/releases/tag/v0.2.0).

## At a glance

A rebuilt local interface, a set of input-handling fixes, and — the part worth
reading before you use a ranking — a measured limitation on how much of a
ranking actually depends on your sequence.

No model was retrained, no representation changed, and no published metric,
prediction or evaluation file was touched. The inference bundle is **unchanged** — it still verifies
against the manifest shipped with v0.2.0, every member digest matching — so the
v0.2.0 bundle archive continues to work and does not need re-downloading, and
scores for a given query are the same as they were.

## The limitation to read first

On a held-out protein, reading your sequence gives **no demonstrated average
improvement** over a ranking that ignores it.

Measured on the checkpoint this bundle actually ships, on its own cold-protein
test partition — a **census of every qualifying target**, not a sample:

| | |
| --- | --- |
| Targets | 244 |
| Labelled pair observations | 79,493 |
| Distinct compounds | 59,912 |
| Macro AUROC, target-specific | **0.6164** |
| Macro AUROC, ignores the query | **0.6224** |
| Random floor | 0.5032 |
| Mean difference | **−0.0060**, 95% CI [−0.019, +0.007] |
| Better on | 112 of 244 targets |
| Wilcoxon signed-rank | p = 0.351 |

No average advantage is demonstrated. **This is not a claim that the two are
equivalent** — no equivalence test was run and no margin was declared. The
direction holds across the bundled-library subset and all three declared
thresholds.

Your sequence does change the ranking: 37 per-target intervals exclude zero
favouring the model and 50 favouring the baseline. Those per-target intervals are
**exploratory and unadjusted for 244 comparisons** — roughly 6 each way would
exclude zero by chance — so they describe spread and do not identify particular
targets as better or worse.

Two bounds. It is one checkpoint on one split. And **30.3% of the evaluated
compounds are molecules the fit had already seen** against other proteins,
because a cold-protein split holds out proteins and not chemistry — so this is a
held-out-protein result on substantially familiar chemistry and says nothing
about new chemistry.

### This is separate from the benchmark in the README

The repository's Key results table reports the historical M11h comparison — a
**different experiment, different checkpoints, different split and a different
comparator**. The bundle does not ship an M11h model: its checkpoint digest
`934adcdb…` is not among the five M11h checkpoints. The benchmark's dual-encoder
figure of 0.781229 therefore describes a model that is not what this release
runs, and **0.6164 is not a regression from it** — the two are not on a
comparable scale and neither checks the other.

An earlier twelve-target panel appeared to show a +0.11 AUROC advantage. Eight of
those twelve targets were in the checkpoint's training partition and the
advantage sat entirely with them; that panel is retained as
[`labelled_panel.md`](../../reports/diagnostics/labelled_panel.md) with the
exposure analysis, and the census above supersedes it as the estimate.

The interface says so where a ranking is read: *"Rankings combine compound
preferences with information from your sequence. Performance varies by target;
accuracy for unfamiliar targets has not been established."*

Full method, every denominator, exclusions and declared checks:
[`checkpoint_bound_evaluation.md`](../../reports/diagnostics/checkpoint_bound_evaluation.md).

## Interface

The local browser interface (`uv run seq2lead web`) was rebuilt as a three-zone
workbench. Still localhost-only, still no account, no upload and no public
endpoint; still the same inference code as the CLI, with tests asserting the rows
match `seq2lead.inference.rank` exactly.

- **Every ranking opens with its score distribution** — a histogram of all 25,000
  scores for your query with the kept rows marked, plus quartiles and standard
  deviation. A predicted pKi of 9.17 means little without the spread it came out
  of, and measured spreads are narrow.
- **Compound detail panel** — select any ranked row or library tile for a large
  depiction, the full SMILES with a copy button, and ten computed properties
  (formula, MW, cLogP, TPSA, HBD, HBA, rotatable bonds, rings, heavy atoms,
  stereocentres). Computed with RDKit from the structure, not predicted; none of
  them took part in ranking.
- **Larger, sharper depictions** throughout, drawn at the size they are displayed.
- **Library browser** with molecular weight and TPSA per tile, and a search
  correctly labelled as a **substring** match over identifier and SMILES text —
  it is not a structure or similarity search.
- **Exports** — CSV byte-for-byte identical to the CLI's, caveat preamble
  included, plus shortlisted identifiers as a plain list.
- **Advanced settings** collapse out of the way: molecular-weight and TPSA
  windows, and diversity selection with a Tanimoto cut-off. Filters act on the
  candidate pool that was kept, not over the whole library.
- **Candidate pool and shortlist are now distinguished** in the interface and the
  documentation. Every compound is always scored; the pool sets how many rows
  come back, and shortlisting is a view over those rows that never re-scores or
  re-ranks.
- **FASTA file picker**, read in the page — nothing is uploaded.
- **Accessibility**: verified by driving a real browser. No horizontal page
  scroll at 320, 390, 834 or 1600 px; a visible focus ring on every in-page tab
  stop; arrow keys between ranked rows, Enter to open a compound, focus returning
  to the row on close; contrast at least 4.5:1 for every colour pair in both the
  light and dark schemes, worst measured 5.51.

## Fixes

Each was reproduced before it was fixed.

- Non-finite (`nan`, `inf`, `1e400`), unparseable and negative property bounds
  returned HTTP 200 with `total=0`, which reads as an empty library. Now 400 with
  a specific message.
- An inverted window (`min_mw` above `max_mw`) returned nothing with no
  explanation.
- `page` and `page_size` outside their ranges were silently clamped, so the page
  shown was not the page requested.
- A legacy `;` preamble line in a FASTA file was concatenated onto the residues
  and embedded as sequence.
- A byte-order mark hid the leading `>`, so the header was lost and the whole
  file was read as one bare sequence.
- The depiction cache was keyed on row alone, so a second bundle's row 0 served
  the first bundle's structure. Now keyed by bundle identity, row and size.
- Descriptors were recomputed for the whole library on every filtered page
  request; now cached per structure (measured 1.52 s → 0.01 s on the second page).
- Trailing stop codons (`*`) are removed with a note rather than rejected, and a
  sequence containing digits now names the likely cause — a numbered or aligned
  view pasted in.

## Documentation

- The README no longer claims there is no interface.
- The bundled library's selection rule is stated exactly: every compound with at
  least one exact-relation Ki measurement in the pinned release, ordered by
  ascending compound id, capped at the first 25,000 — a **deterministic prefix of
  232,721 eligible compounds, not a representative sample**.
- Database preparation and standalone inference are separated, with a table of
  what each needs.
- The browser's model loading, job serialisation, cancellation and exports are
  documented.

## Diagnostics added

- **Repeated compound projections** — 24,702 distinct vectors among 25,000 rows;
  218 groups covering 516 compounds. Traced to ECFP4 at radius 2 being unable to
  distinguish polymethylene chain length: across all 218 groups, 218 have
  identical fingerprints and 0 have differing ones. The repetition is upstream of
  the learned model.
- **Query panel** (unlabelled, exploratory) and the **labelled panel** above.

## Metadata

The package reported `0.1.0` throughout the v0.2.0 release. `pyproject.toml`,
`seq2lead.__version__` and `CITATION.cff` are aligned at **0.3.0**.

## Upgrading

```bash
git fetch --tags && git checkout v0.3.0
uv sync --all-groups
```

Your existing `seq2lead-bundle` continues to work; the bundle is unchanged from
v0.2.0 and ESM-2 weights are untouched.

## Still true from v0.2.0

Results are exploratory. Predicted pKi is a ranking score — not a calibrated
probability, not a binding probability, and not evidence that any compound binds.
Nothing in this project has been experimentally tested.
