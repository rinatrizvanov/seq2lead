# M9 contract — dual encoder and the ranking CLI

Written before any M9 model was fitted. It fixes the architecture, the objective,
the search budget, the selection rule and what the resulting numbers may be
claimed to mean.

Status inherited from M4/M5: the endpoint is
**`provisional_pooled_for_exploratory_benchmark`**. Ki pooling across assays was
never validated. Every number here inherits that.

## 1. These comparisons are exploratory, not confirmatory

**The M8 test partitions have already been inspected.** The baseline leaderboard
was read, discussed and corrected twice against those same test sets. A model
compared against them now is being compared on data the project has already
looked at.

So M9 test numbers are **exploratory**. They are not a held-out confirmatory
result, and this document does not present them as one. What keeps them honest
rather than meaningless:

- **Configuration selection uses validation only.** No test score selects a
  configuration, a stopping point, or a decision to keep tuning.
- **Configurations are frozen before test scoring**, and the frozen set is
  recorded in `reports/results/m9_selection.json` before the test pass runs.
- A genuinely confirmatory result needs a partition nobody has looked at. The
  honest route is the true as-of temporal evaluation deferred to M11, which
  trains on an older archived BindingDB release and tests on pairs new in a
  later one.

`label_reversal-v3` stays **unscored** for the whole pass, as in M8. It is
`diagnostic_frozen`, and scoring it here — including to justify deferring an
ablation — would spend the one diagnostic that has to come last.

## 2. Pinned inputs

Identical to M8, by digest, so the comparison is like-for-like:

| Input | Identity |

| endpoint | `ki-pki6-v2` (id 96), θ = pKi 6.0 |
| compound features | `ecfp4-compound-42351e003acb` (chiral ECFP4, 2,048 bits bit-packed) |
| protein features | `esm2-target-48cfa09487ce` (ESM-2 650M, mean-pooled, 1,280-d) |

Cohorts are M8's: the same eligibility rules, the same 179 unusable-fingerprint

**`train_only`** with partition-specific endpoints, and `new` remains the
headline stratum.

Both encoders read **frozen** caches. No PLM is fine-tuned in this pass.

## 3. Architecture and the scoring head

Two independent projections into a shared space:

- compound: 2,048-bit ECFP4 → `Linear(2048, h)` → ReLU → `Linear(h, h)`
- protein: 1,280-d ESM-2 → `Linear(1280, h)` → ReLU → `Linear(h, h)`

Compound and protein towers never see each other's input, so **every compound
projection can be precomputed once** and reused across targets. That is the
property the ranking CLI depends on.

### What the head predicts, and in what units

This needs stating precisely, because the obvious choices are wrong:

- **Cosine similarity alone cannot represent pKi.** It is bounded to [-1, 1] and
  the labels are roughly 2–12.
- **`sigmoid(cosine)` is not pKi either**, and it is *not* automatically a
  calibrated probability. A sigmoid produces a number in (0, 1); calling it a
  probability requires a reliability diagram and an ECE, neither of which this
  pass computes.

So the regression head is an explicit **affine map on the cosine**:

```
score = a * cos(z_compound, z_protein) + b        # a, b trainable scalars
```

`a` and `b` are trainable, initialised from the training-label spread (`a` to
half the label range, `b` to the training mean), and the output is **in pKi
units** — directly comparable with the M8 baselines. The bounded cosine times a
learned scale is the whole expressive range; that is a real constraint of this
architecture and is reported as a limitation, not hidden.

Ranking uses the same score. Because `a > 0` is learned and shared, the ranking
induced within a target is the cosine ranking.

## 4. Objective and training

**Exact-label regression**, matching the M8 primary comparison: MSE against
`pair_regression.p_median` on eligible exact-relation pairs. Censored records
supply **no** regression target — an interval is not a point — but remain
eligible for ranking evaluation, exactly as in M8.

Preprocessing is fitted on **training inputs only**. The protein block is
standardised with training mean and scale; fingerprint bits are 0/1 and are left
alone. The frozen transform is applied unchanged to validation, test and the CLI.

## 5. Search budget — small, declared, validation-only

| Setting | Values |
| --- | --- |
| projection dim `h` | **256, 512** |
| learning rate | 1e-3 (fixed) |
| batch size | 512 (fixed) |
| max epochs | 20, early stopping patience 5 |
| optimiser | Adam, default betas |

**Two configurations.** Not a Cartesian sweep — the original plan listed four
projection dims, four contrastive margins, three fingerprint sizes and two PLMs,
which is 96 fits per split before seeds. That is not bounded work and it is not
attempted here.

**Selection metric: validation RMSE**, lowest wins, evaluated once per epoch.
**Stopping rule:** early stop after 5 epochs without improvement; the
best-validation checkpoint is restored.

**Fallback for insufficient validation coverage:** a split whose validation
partition yields fewer than 1,000 eligible pairs or fewer than 20 targets is
declared to have insufficient coverage; the configuration selected on
`random_pair-v3` is carried over, and the report says so per split rather than
selecting on a partition too small to separate two configurations.

## 6. Contrastive training is an ablation, and is deferred

It is **not** in the bounded core. If it is implemented later:

- negatives are drawn **only from eligible measured training evidence** —
  measured inactives for that target. An unmeasured pair is never a negative.
- pairs the endpoint marked contradictory, discordant or ambiguous are excluded
  from confident negative labels; unresolved evidence cannot define a negative.
- the objective, the sampling policy and the negative pool size are documented
  before it is run.

## 7. Candidate library for the CLI

The first runnable path uses the **curated database library**, declared here so
it cannot be reverse-engineered from desired output:

- **Selection rule:** compounds with at least one eligible exact-relation Ki
  measurement in the pinned release, ordered by `compound.id`, capped at
  **25,000**. Ordering by a stable surrogate key and taking a prefix is
  arbitrary with respect to predicted affinity, which is the point.
- Versioned as `curated-ki-25k-v1` with the member id list digested, so a
  ranking can be reproduced exactly.

Compounds are **not** chosen by predicted score, by similarity to a query, or by
any property of the model.

## 8. What the CLI may claim

- It returns **ranking scores in pKi units**, not probabilities and not
  calibrated confidences.
- Known measurements may be displayed, labelled **prior measured evidence**, and
  rendered separately from predictions. They are **not** independent validation
  of the ranking.
- Nothing is described as experimentally validated. No compound surfaced here
  has been tested by this project.
- Evaluation-mode evidence stays restricted to the active experiment's training
  partition.

## 9. Artifacts

Everything M9 writes lives under experiment-scoped paths so it cannot overwrite
M8:

| Artifact | Path |
| --- | --- |
| checkpoints, transforms, history | `data/m9/<run>/` |
| predictions | `data/predictions_m9/` |

Saved per run: model state, the frozen preprocessing transform, per-epoch
training history, parameter count, config digest, code version and artifact
digests.

## 10. Acceptance criteria

**Better scores are not one of them.** This pass is accepted when:

1. The model trains, and the fixtures in §11 pass.
2. Configurations are selected on validation and frozen before test scoring.
3. It is evaluated on the four active splits under M8's corrected metrics and
   cohorts, reported beside B0, B1, B3L and B4 with their real definitions.
4. Temporal new/recurrent, near-homolog and long-sequence breakouts are
   preserved, with prevalence and scored/skipped counts.
5. Every number is reproducible from saved artifacts.
6. Losses and undefined metrics are reported plainly.

A dual encoder that loses to B4 or to B3L is a result, not a failure to fix by
tuning against the test set.

## 11. Pre-flight verification

Before any expensive run, on small isolated fixtures:

- every intended parameter receives a gradient;
- a tiny training set can be overfit (the optimiser is wired correctly);
- the score depends on **both** inputs — perturbing either moves it;
- batched pair scoring equals scoring against a precomputed compound matrix, to
  a declared tolerance (the CLI's correctness rests on this);
- save/load round-trips predictions within a declared tolerance;
- preprocessing, retrieval and evidence never read held-out activities.

Fixture writes are isolated from the corpus by the M7 schema isolation.

One bounded training run is measured, and its actual runtime scopes the rest.
